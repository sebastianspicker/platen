# Frontend screenshots

This folder contains curated local proof of the redesigned browser surface. It
is not a marketing gallery and does not replace keyboard, accessibility, error,
or workflow testing.

## Provenance

Every checked-in image must have a matching entry in `manifest.json` with:

- `path`: repository-relative image path;
- `route`: rendered route (`editor`, `workflows`, `plugins`, or `trust`);
- `viewport`: width and height in CSS pixels;
- `browser`: browser name and version;
- `source`: fixture name and SHA-256, or `null` for the no-document state;
- `state`: explicit UI state (`empty`, `ready`, `catalog`, etc.);
- `capturedAt`: ISO-8601 timestamp in UTC;
- `notes`: short factual description of what the image proves.

Do not capture real user PDFs, credentials, loopback tokens, or host paths. Use
the deterministic fixture generated by `tests/pdf-fixture.js`, staged outside
the repository. Temporary baseline images stay outside the repository. Replace an image
only when the UI or fixture changes, and update its manifest entry in the same
change.

## Gallery

The current Platen set covers Workspace, Operations, Coverage, and Trust at
1440×1000 and 390×844:

- `editor-ready.png` and `editor-mobile.png`;
- `workflows.png` and `workflows-mobile.png`;
- `capability-catalog.png` and `capability-mobile.png`;
- `trust-limits.png` and `trust-mobile.png`.

The 2026-07-24 captures used Google Chrome 150.0.7871.182 and an in-process local
application handler. The desktop ready, workflow, and trust states use the
generated two-page fixture; the catalog and mobile states use no document.
The harness reported no browser console errors, page errors, or document-level
horizontal overflow. Exact provenance is recorded in `manifest.json`.

Images are evidence of the visible surface only. The accompanying frontend
brief and test output are the source of truth for behavior and accessibility.
