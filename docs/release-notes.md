# Release notes

The authoritative note for the current candidate is
[0.3.0-alpha.1](releases/0.3.0-alpha.1.md). Repository-level version history is
maintained in [CHANGELOG](../CHANGELOG.md), and current publication blockers are
recorded in [RELEASE_STATUS](../RELEASE_STATUS.md).

Release notes must describe shipped behavior and known limitations. Do not use
them as implementation plans or as evidence that an unverified capability is
available. Keep the candidate identity aligned with `package.json`, the release
validator, README, changelog, and release status.

Creating or editing release notes does not authorize a commit, tag, push,
GitHub release, or distribution artifact. Follow [Releasing](RELEASING.md) when
publication is explicitly authorized.
